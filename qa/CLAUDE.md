# qa/CLAUDE.md

Manual QA tree for the NativeScript **snippets** extension. Two subtrees drive a QA pass:
`checklists/` (what to test) and `workspace/` (fixtures to test with). A standalone
`demo-workspace/` (realistic flavor sandbox) sits alongside them — see the bottom of this file.

This whole directory is **dev-only**: `.vscodeignore` excludes `qa/**` from the published
`.vsix`. Nothing here ships to users.

## What a QA pass verifies

This is a **declarative snippets extension** — no commands, settings, activation code, or
drag-and-drop. So every checklist item is the same shape: open a file of a contributed
language, type an `ns-*` prefix, accept the completion, verify the inserted body + tab stops.
There is nothing to click. Do not add command/setting/DnD cases — they don't exist here.

## Checklist ↔ workspace sync rule

Every checklist has a 1:1 workspace counterpart:

```
checklists/general.md   ↔  workspace/general/
checklists/angular.md   ↔  workspace/angular/
checklists/core.md      ↔  workspace/core/
checklists/vue.md       ↔  workspace/vue/
checklists/react.md     ↔  workspace/react/
checklists/svelte.md    ↔  workspace/svelte/
```

**Sync direction is one-way — the checklist drives the workspace:**

- Checklist updated → verify `workspace/{flavor}/` has every fixture the checklist references.
  Add missing files; update content if the checklist changed expectations.
- Workspace updated → do **not** update the checklist. The workspace may hold extra scratch
  files the checklist doesn't mention.

## Propagation rule — checklist changes ripple outward

When any file in `checklists/` is added, removed, or updated, check these for staleness and
update them:

1. **`checklists/README.md`** and **`checklists/CLAUDE.md`** — inventory tables, case counts, scope.
2. **`README.md`** and **`CLAUDE.md`** (this directory) — flavor inventory table, mapping, order.
3. **`workspace/README.md`** — flavors table, file counts.
4. **`workspace/{flavor}/`** — add/update/remove fixtures so every path the checklist references
   exists; update that folder's `README.md` (tree, mapping, counts) and `CLAUDE.md` (edit rules).

The reverse does **not** apply: workspace-only changes don't propagate back to the checklists.

## Source-of-truth rule for asserted expansions

The snippet bodies a checklist quotes must match the **generated JSON** under
`../snippets/<flavor>/*.json` exactly (those files are themselves generated by
`../tools/render.js` from the `@nativescript/core` types). When the generator or the core
version changes and snippets are regenerated, re-verify the quoted expansions in the affected
checklists by running **`/_rot qa/**`** — it diffs every quoted body, tab-stop index, and
inherited-count in `qa/` against the current generated JSON and reports the drift. This audit is
the deliberate guardrail; there is intentionally no build-time gate for `qa/` quote drift. Never
hand-edit `../snippets/**` to match a checklist — fix the checklist.

## Execution order

`general.md` runs first. It covers flavor-neutral behavior — prefix grammar, the variant model
(`bare`/`-prop`/`-comp`/`-snippet-N`), tab-stop semantics, IntelliSense trigger mechanics, the
`Source:` hover, and **language scoping**. The five per-flavor checklists assume `general.md`
passed and test only that flavor's **delta** (tag case, event/two-way syntax, icons, excluded
elements). Do not duplicate `general.md` items in the per-flavor checklists.

## Adding a new flavor (if the extension ever grows one)

1. Create `checklists/{flavor}.md` with the flavor-specific cases.
2. Create `workspace/{flavor}/` with every fixture the checklist references + its `README.md`/`CLAUDE.md`.
3. Add the flavor to the tables in `checklists/README.md`, `workspace/README.md`, and this dir's `README.md`.

## demo-workspace (standalone)

`demo-workspace/` is a NativeScript flavor sandbox — one component file per flavor (`angular/`,
`core/`, `vue/`, `react/`, `svelte/`, the same flavor layout as `workspace/`) for trying snippets
in context. It sits **outside** the checklist↔workspace model: nothing in `checklists/` references
it, and the propagation rules do not apply.

- **Nothing to install — no `package.json`/`tsconfig.json`/`node_modules`.** Snippets are
  declarative and expand purely from the prefix + the file's language id, regardless of project
  setup. The component files may reference framework packages/globals that aren't installed; that's
  fine — don't "fix" them.
